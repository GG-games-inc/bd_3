### Задание 1

`**1. Активный Master-сервер и пассивный репликационный Slave-сервер:**  
Повышение отказоустойчивости: Если мастер-сервер выходит из строя, можно вручную переключиться на slave-сервер.  Улучшение производительности чтения: Всю нагрузку от аналитических запросов, отчетов и сложных выборок можно перенести на slave-сервер, разгрузив тем самым мастер для критически важных операций записи.  
Географическое распределение: Slave-сервер можно разместить в другом регионе для уменьшения задержки для локальных пользователей.`

`**2. Master-сервер и несколько Slave-серверов:**  
Массовое масштабирование чтения: Это главное преимущество. Нагрузку на чтение можно распределить между множеством slave-серверов с помощью балансировщика нагрузки.  
Высокая доступность и отказоустойчивость: При выходе из строя одного slave-сервера, другие продолжают работать. Система может выдержать несколько отказов в части чтения.  
Гибкость развертывания: Позволяет использовать менее мощное железо для slave-серверов, так как нагрузка распределена.`

`**Принципы построения системы:**  
Вертикальный шаринг: Разделение таблиц по разным серверам на основе их функциональной принадлежности. Таблицы имеют разную нагрузку и предметную область.  
Горизонтальный шаринг: Разделение одной таблицы на множество частей (шардов) по определенному ключу, которые располагаются на разных серверах. Когда объем данных или нагрузка на одну таблицу становятся слишком велики.  
Разграничение: Сначала применяем вертикальный шаринг, чтобы изолировать разные сущности. Затем, для таблиц, которые этого требуют, применяем горизонтальный шаринг.`
